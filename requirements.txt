# Runtime dependencies, pinned EXACTLY on purpose. Two reasons, both learned
# the hard way — see CLAUDE.md "Dependency pinning" before loosening anything:
#
#   1. Reproducibility. The Dockerfile runs `pip install -r requirements.txt`,
#      so a bare `>=` floor installs whatever is latest at image-build time.
#      That is not a theoretical hazard here: this file said `gunicorn>=23.0`
#      and `anthropic>=0.40` while the box was running gunicorn 26.2.0 and
#      anthropic 1.7.0 — two major bumps that entered production on an image
#      rebuild, with no PR and no review.
#   2. Dependabot. GitHub's `dependabot/fetch-metadata` misparses a *bounded*
#      range: `pypdf>=6.14.2,<7` produced the PR title "Update pypdf requirement
#      from <7,>=6.14.2 to >=6.19.0,<7" and was reported as
#      `version-update:semver-major`, so ci.yml's auto-merge gate (correctly)
#      refused a minor bump and PR #21 stuck forever. An exact pin produces
#      "Bump X from A to B", which parses correctly.
#
# Every version below is the version running in production. Transitive deps
# (Werkzeug, httpx2, soupsieve, ...) are left to the resolver; pin one here only
# when there is a specific reason, with the reason in a comment.

gunicorn==26.2.0

requests==2.34.2
beautifulsoup4==4.15.0
# PDF-era official transcript extraction (episodes ~385-410).
